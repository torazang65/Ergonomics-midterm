## 1단계 공감과 관찰

과업 중심 페르소나는 집에서 Mac으로 과제·공부를 하며 여러 앱 창을 동시에 띄워 두고(Kakaotalk Reference.png), 터치패드 창 개요로 창을 전환하는(자기보고) 학생이다. 친구에게 과제를 묻기 위해 특정 카카오톡 대화로 돌아가려 한다. 본인 1명의 사례에 한정하며 나이·전공·숙련도·감정 점수·빈도는 추가하지 않는다. 집에서의 공부는 시험지 PDF p.9의 "학생들의 학습과 연구 현장"에 해당하는 것으로 연결한다.

| 단계 | 확인된 화면·행동 | 과업상 의미 |
|---|---|---|
| 창 개요 | 다른 앱은 창 하나라 빨리 찾지만, 카카오톡은 채팅마다 창이 있어 비슷한 썸네일 중 목표를 바로 찾지 못함 | 불편이 시작된 단계. 목록 창도 썸네일 하나 |
| Dock 복귀 | 카카오톡 창 4개가 한꺼번에 뜸. 목록은 열려 있었으나 다른 창에 가려짐 | 기존 목록 기능이 보이지 않아 쓰이지 못함 |
| 우회 행동 | 창을 하나씩 닫으며 목표를 찾음 | 시스템이 요구한 절차가 아니라 사용자의 적응 |

페인 포인트: 다른 앱처럼 창 개요에서 바로 고를 수 없고, 원하는 친구의 창을 찾으려고 창을 하나씩 닫아야 했다. 소요 시간·오선택·인지 부하의 실측값은 없다. 채널·광고 분류 문제는 포함하지 않는다.

## 2단계 문제 정의

현재 문제 정의: 학습 중 특정 친구의 대화로 돌아가려 할 때, 카카오톡이 채팅마다 별도 창을 만들어 창 개요와 겹친 화면에서 비슷한 창 여러 개 중 목표 상대를 구별·선택해야 하는 부담.

| 원인 가설 | 근거와 적용할 원리 | 원본 PDF 페이지 | 한계 |
|---|---|---|---|
| 같은 외형의 창들이 묶음으로 지각되고 그 안의 구별은 세부에 의존 | 같은 배경·배치로 '카카오톡 창들'로 묶여 보임. 앱 인식에는 도움이 되나 목표 상대 구별에는 초점 처리가 필요. 유사성은 재인 혼동의 원인 | 「3장 보충 2026.pdf」 p.71, 89, 101; 「2026 4장 보충.pdf」 p.53 | 실제 크기 창에는 인원수·프로필 등 다른 단서도 있음. 오선택 미기록 |
| 썸네일에서 이름 글자의 시각이 작아짐 | 시각은 대상 크기와 거리로 정해지고 시력은 세부 식별 능력. 썸네일 축소로 이름 글자가 작아짐 | 「5장 보충 vision and visual acuity.pdf」 p.9 | 화면 거리·글자 크기 미측정. 시각 값 계산 안 함 |
| 탐색 안내 정보가 없는 탐색 | 창 개요 배치는 이름 순서 등 안내 정보를 주지 않아 비슷한 창을 하나씩 확인하게 됨. 메뉴 같은 안내 정보가 있으면 구조화된 탐색 가능. 기존 목록은 창 개요에서 썸네일 하나, 일반 화면에서는 가려짐 | 「3장 보충 2026.pdf」 p.97, 98 | 탐색 시간·시선 미측정. 불편 시점 화면 확인 필요 |
| 과업과 창 구조의 부적합 | 한 상대에게 질문하는 과업에 채팅마다 창이 생기는 구조가 맞지 않아 사용자가 창 닫기로 적응 | 「Lecture 1 인간공학 소개 2026.pdf」 p.25 | 창 닫기는 사용자의 선택이며 강제된 절차가 아님 |

각 인용 페이지는 원문 PDF에서 추출해 확인했고, 그림 중심인 3장 p.71은 렌더링해 확인했다.

## 3단계 아이디어 도출과 선택

HMW: 어떻게 하면 학습 중인 학생이 다른 앱을 찾을 때처럼, 창 개요에서 카카오톡을 한 번에 찾고 원하는 친구의 대화로 바로 갈 수 있을까?

| 대안 | 대응 원인·인지적 한계 | 새 부담 | 검증 |
|---|---|---|---|
| A 통합 대화 창 | 유사성·과업 부적합(창 개요에 카카오톡 창 하나), 시각·탐색(창 안의 읽히는 이름 목록) | 창 관리 구조 변경, 목표가 마지막 대화와 다르면 선택 한 번 추가, 동시 비교 시 분리 | 창 개요부터 목표 도달까지 비교 |
| B 대화창 상단 대화목록 버튼 | 가려진 목록을 앞으로 | 목록 선택은 이미 존재, 창 개요 단계·창 누적 그대로 | 제외 |
| C 개별 창 식별 강화 | 유사성·시각(큰 상대 이름) | 창이 여러 개인 구조 유지, 축소율에 따른 한계 | 같은 창 수에서 탐지 비교 |
| D 기존 목록 경로 안내 | 기억 의존 | 창 개요·가림 문제 그대로 | 비교 기준 |

선택은 A, 보조는 C(분리한 창에 적용)다. 효과·실현 가능성·새 부담·검증 가능성을 기준으로 한 판단이며 실측 성능 비교는 아니다. A는 함께 쓰는 목록과 대화를 한 창에 두어 근접 부합성(「6장 디스플레이 보충 2026.pdf」 p.32)과도 연결되지만 보조 근거로만 쓴다. WhatsApp·Discord 비교는 work/q3/pc-ui-comparison.md에 있으며 배치 참고로만 쓴다.

## 4단계 프로토타입

1. 기본은 통합 창 하나다. 왼쪽에 열었던 대화 목록, 오른쪽에 선택한 대화를 둔다. 목록에서 대화를 열어도 새 창을 만들지 않으므로 창 개요에 카카오톡 창은 하나만 나타난다.
2. 창 제목과 대화 상단에 현재 상대 이름을 크게 표시하고, 목록의 선택 행은 테두리·배경과 '선택됨' 문자로 상단 이름과 대응시킨다(평가차를 줄이는 피드백, 「8장 콘트롤 보충.pdf」 p.4).
3. 목록 항목은 자동 재정렬하지 않는다. 대화별 초안과 읽던 위치를 유지한다.
4. 나란히 봐야 할 때만 '별도 창으로 보기'로 분리하고 '통합 창으로 복귀'로 되돌린다. 분리한 창에는 큰 상대 이름(C)을 적용한다.

모형: work/q3/kakao-return.html. 그림: output/q3-prototype.png(현재 창 개요 캡처, 제안 창 개요 모의 화면, 통합 창 모형의 세 장면). 모형은 통합 창 안의 대화 선택, 상단·창 제목 이름 갱신, 선택 표시, 대화별 초안 유지, 내부 패널로 예시한 별도 보기를 구현했다. 실제 OS 창 분리·창 개요·Dock 동작과 읽던 위치 보존은 구현하지 않았다. 제외한 B의 모형·그림은 work/q3/kakao-list-return.html과 output/q3-list-return-prototype.png로 남긴다.

## 5단계 테스트 계획

미수행 계획이다. 시험지 PDF p.9는 5단계를 명시하나 답안 칸은 p.11의 프로토타입까지다. 추가 공지로 실수행을 요구한다면 확인한다.

- 과업: 창 개요에서 시작해 지시받은 상대의 대화를 열고 이름을 확인한다.
- 조건: 기존 구조(채팅마다 창)와 A. 목표가 마지막 대화인 경우와 다른 대화인 경우를 모두 포함한다. 기존 조건에서는 목록 선택·Dock 메뉴·창 닫기 등 모든 경로를 허용한다.
- 통제: 열린 대화 수, 상대 정보, 다른 앱 창 수, 창 크기, 해상도를 맞춘다. 조건 순서를 교차한다.
- 지표: 완료 여부, 전체 시간, 잘못된 상대 선택, 창 개요에서 카카오톡을 고르기까지의 시간. 닫은 창 수는 보조 지표다.
- 참가자: 사용자 본인은 설계 의도를 알고 있어 첫 사용 측정 대상이 될 수 없다. 본인만의 결과는 예비 평가로 한정한다.
- 현재 모형으로는 창 개요를 포함한 전체 시간을 측정할 수 없어, 같은 충실도의 기존 구조 모형을 준비하기 전에는 통합 창 안의 상대 선택과 초안 유지의 형성 평가만 가능하다.

방법 근거는 「2장 보충 인간공학 연구방법론.pdf」 PDF p.22-23, 32, 사용성 지표는 「Lecture 1 인간공학 소개 2026.pdf」 PDF p.51, 53이다.

## 남은 확인

창 개요 캡처가 불편 시점의 화면인지, 화면 거리·이름 글자 크기, 앱·OS 버전, 카카오톡에 이미 비슷한 통합 보기 설정이 있는지, 답안 칸 크기, 실제 사용자 평가는 확인 필요다. 두 번째 후속 답변의 '대화창'이 대화 목록 창이라는 해석도 재확인하지 않았다.
