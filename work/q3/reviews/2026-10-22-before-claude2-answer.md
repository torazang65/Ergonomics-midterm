# 문제 3 답안 초안

## 1단계 공감과 관찰

10월 22일 저녁 집에서 Mac으로 과제·공부를 하던 중(학습 현장), 친구에게 과제를 질문하려고 카카오톡 대화로 돌아가는 과정에서 불편을 체험했다. 평소처럼 터치패드에서 네 손가락을 위로 쓸어 창 개요를 열었다. 다른 앱은 창이 하나라 금방 찾을 수 있었지만, **카카오톡은 채팅마다 창이 하나씩 생겨 비슷하게 생긴 창 여러 개 중 원하는 친구의 창을 바로 찾지 못했다**(그림 1). Dock에서 카카오톡을 열자 창 4개가 한꺼번에 나타났고, 결국 창을 하나씩 닫으며 원하는 친구의 창을 찾았다.

카카오톡에는 대화 목록에서 상대를 고르면 해당 대화창이 앞으로 오는 기능이 이미 있다. 그러나 창 개요에서는 목록 창도 썸네일 하나일 뿐이었고, Dock으로 돌아갔을 때는 목록 창이 다른 창들에 가려져 있었다. 기존 기능이 있어도 이 상황에서는 쓰이지 못한 것이다.

페르소나는 **여러 앱 창을 동시에 띄워 두고 터치패드 창 개요로 전환하며 공부하다가, 친구에게 질문하려고 특정 대화로 돌아가는 Mac 사용자 학생**이다. 본인 1명의 경험에 근거한 과업 중심 페르소나다. 핵심 페인 포인트는 **다른 앱처럼 창 개요에서 바로 고를 수 없고, 원하는 친구의 창을 찾으려고 창을 하나씩 닫아야 했다는 것**이다. 소요 시간·오선택 횟수는 측정하지 않았다.

## 2단계 문제 정의

선정 문제는 **학습 중 특정 친구의 대화로 돌아가려 할 때, 카카오톡이 채팅마다 별도 창을 만들어 비슷한 창 여러 개 중 목표 상대를 구별·선택해야 하는 부담**이다.

| 원인 | 인간공학적 진단 |
|---|---|
| 같은 외형의 창들이 하나의 묶음으로 보임 | 카카오톡 창들은 같은 배경색과 배치를 공유해 유사성 원리에 따라 '카카오톡 창들'이라는 묶음으로 지각된다(「3장 보충 2026.pdf」 PDF p.71, 101). 이는 앱을 알아보는 데는 도움이 되지만, 목표는 그 안에서 특정 상대 하나를 고르는 것이다. 묶음 안에서 개별 창을 구별하려면 세부를 보는 초점 처리가 필요하다(같은 자료 PDF p.89). 기억 측면에서도 유사성은 재인 실패(혼동)의 원인으로 제시된다(「2026 4장 보충.pdf」 PDF p.53). 다른 앱은 앱을 알아보는 순간 탐색이 끝나지만 카카오톡은 한 단계가 더 필요하다. |
| 썸네일에서 상대 이름이 작아짐 | 시각은 대상의 크기와 거리로 정해지며, 시력은 세부를 식별하는 능력이다(「5장 보충 vision and visual acuity.pdf」 PDF p.9). 창 개요에서 창이 썸네일로 줄면 상대를 구별할 단서인 이름 글자도 작아져 같은 거리에서 시각이 작아지므로, 이름을 읽어 구별하기 어려워진다. |
| 탐색을 안내하는 정보가 없음 | 창 개요의 배치는 이름 순서 같은 안내 정보를 주지 않아 비슷한 창을 하나씩 확인하는 시각 탐색이 된다(「3장 보충 2026.pdf」 PDF p.97). 메뉴처럼 화면에 탐색 안내 정보가 있으면 구조화된 탐색이 가능하지만(같은 자료 PDF p.98), 그 역할을 할 목록 창은 창 개요에서 썸네일 하나로 줄고 일반 화면에서는 가려져 있었다. |
| 과업과 창 구조가 맞지 않음 | 과업은 한 친구에게 질문하는 것인데, 채팅마다 창이 생기는 구조 때문에 사용자가 창을 하나씩 닫는 방식으로 적응해야 했다. 사람이 시스템에 맞추기보다 작업을 사람에게 맞춰야 한다는 원칙에 어긋난다(「Lecture 1 인간공학 소개 2026.pdf」 PDF p.25). |

화면 거리와 글자 크기, 탐색 시간과 오선택은 측정하지 않았으므로 위 원인은 관찰과 자기보고에 근거한 가설이다.

## 3단계 아이디어 도출

**어떻게 하면 학습 중인 학생이 다른 앱을 찾을 때처럼, 창 개요에서 카카오톡을 한 번에 찾고 원하는 친구의 대화로 바로 갈 수 있을까?**

| 대안 | 대응하는 원인·인지적 한계 | 새 부담과 한계 |
|---|---|---|
| A 통합 대화 창 | 창 개요에 카카오톡 창이 하나만 나타나 묶음 안 구별이 사라지고(유사성·과업 부적합), 창 안에서는 읽을 수 있는 크기의 이름 목록으로 고른다(시각·탐색). | 창 관리 구조를 바꿔야 한다. 목표가 마지막 대화와 다르면 목록에서 한 번 더 골라야 하고, 나란히 볼 때는 분리가 필요하다. |
| B 대화창 상단의 대화목록 버튼 | 가려진 목록을 앞으로 가져온다. | 목록 선택은 이미 있는 기능이고, 창 개요 단계와 창이 쌓이는 구조는 그대로다. |
| C 개별 창 식별 강화 | 창 상단에 큰 상대 이름·프로필을 두어 창 개요에서도 읽히게 한다(유사성·시각). | 창이 여러 개인 구조는 남고 썸네일 축소율에 따라 한계가 있다. |
| D 기존 목록 경로 안내 | 목록에서 고르는 기존 기능을 알린다. | 창 개요 단계와 가림 문제는 그대로다. |

**A를 프로토타입으로 선택하고 C를 보조안으로 둔다.** 불편이 시작된 창 개요 단계에서 카카오톡을 다른 앱처럼 창 하나로 만들어 묶음 안의 구별 단계를 없애고, 창 안에서는 이름 목록으로 고르게 하기 때문이다. B는 이미 있는 목록 기능에 버튼을 더할 뿐 창 개요 단계를 해결하지 못해 제외했다. 함께 쓰는 목록과 대화를 한 창에 두는 점은 근접 부합성과도 연결된다(「6장 디스플레이 보충 2026.pdf」 PDF p.32). 이 선택은 설계 판단이며 실험으로 확인한 결과는 아니다.

## 4단계 프로토타입

카카오톡 데스크톱의 **통합 대화 창**을 제안한다.

![그림 2. 통합 대화 창 제안: 현재 창 개요(실제 캡처), 제안 시 창 개요(모의 화면), 통합 창 안의 대화 선택(모형·가상 대화)](q3-prototype.png)

1. 기본은 통합 창 하나다. 왼쪽에 열었던 대화 목록, 오른쪽에 선택한 대화를 둔다. 목록에서 대화를 열어도 새 창을 만들지 않으므로 창 개요에서 카카오톡은 다른 앱처럼 창 하나로 나타난다.
2. 창 제목과 대화 상단에 현재 상대 이름을 크게 표시하고, 목록의 선택 행은 테두리·배경과 '선택됨' 문자로 상단 이름과 대응시킨다. 고른 결과가 목표와 맞는지 바로 확인하게 해 평가차를 줄이려는 설계다(「8장 콘트롤 보충.pdf」 PDF p.4).
3. 목록 항목은 자동 재정렬하지 않아 위치를 익힐 수 있게 하고, 대화를 바꿔도 대화별 초안과 읽던 위치를 유지한다.
4. 여러 대화를 나란히 봐야 할 때만 '별도 창으로 보기'로 분리하고 '통합 창으로 복귀'로 되돌린다. 분리한 창에는 큰 상대 이름(C)을 적용한다.

모형은 통합 창 안의 대화 선택, 이름·선택 표시, 대화별 초안 유지, 별도 보기를 구현했다. 그림 2의 제안 창 개요는 모의 화면이며, 실제 카카오톡이나 macOS의 창 개요·Dock 동작을 구현한 것은 아니다.

## 5단계 테스트 계획

테스트는 미수행이다. 창 개요에서 시작해 지시받은 친구의 대화를 열고 이름을 확인하는 과업으로, 기존 구조(채팅마다 창)와 통합 창을 같은 충실도의 모형으로 비교한다. 목표가 마지막 대화인 경우와 다른 대화인 경우를 모두 포함하고, 기존 조건에서는 목록 선택·창 닫기 등 모든 경로를 허용한다. 완료 여부·전체 시간·오선택과 창 개요에서 카카오톡을 고르기까지의 시간을 보며, 설계 의도를 아는 본인은 첫 사용 측정 대상에서 제외한다(「2장 보충 인간공학 연구방법론.pdf」 PDF p.22-23, 32).
