# Q3 사용자 추가 설명

2026-10-22 현재 대화에서 사용자가 직접 제공한 설명이다. 기존 evidence/q3/observation.md와 사진은 수정하지 않았다. 아래는 추가 자기보고이며 AI의 현장 관찰이나 실험 결과가 아니다.

## 사용 맥락

- 날짜·장소: 10월 22일 저녁, 집에서 공부 중.
- 하고 있던 일: 과제 및 공부.
- 카카오톡 사용 목적: 친구에게 과제를 물어보기.
- 기기: Mac, 터치패드 사용. macOS·카카오톡 버전 및 디스플레이 사양은 확인 필요.

## 사용자가 설명한 조작 순서

1. 터치패드에서 네 손가락을 위로 쓸어 전체 창 개요를 연다.
2. 이 화면에서 원하는 친구의 대화창을 바로 찾지 못한다.
3. Dock에서 카카오톡을 연다.
4. 열려 있던 창 4개가 한꺼번에 나타난다.
5. 창을 하나씩 닫아 가며 원하는 친구의 창을 찾는다.

원문: “우선 맥에서 손가락4개를 터치패드로 쓸어올려서 전체 탭화면을 봄, 그러나 여기서 바로 친구를 찾을수 없어서, doc에 카카오톡을 열음 -> 그러니까 열려있던 창이 4개가 한번에 뜸 -> 여기서 하나씩 닫아가며 내가 원하는 친구의 창을 찾음.”

## 근거의 한계

- 소요 시간, 닫은 창의 정확한 수, 잘못된 창을 선택한 횟수는 측정하지 않았다.
- 창 개요와 여러 창의 겹침은 기존 캡처와 대조할 수 있다. 조작 순서 전체는 영상이 아닌 사용자의 자기보고에 근거한다.
- 창 닫기가 유일한 방법이거나 시스템이 강제한다는 뜻은 아니다. 이 사용자가 실제로 취한 우회 행동이다.
- 이 경험을 다른 학생 전체나 모든 설정·버전으로 일반화하지 않는다.

## 비교 이미지 출처 추가 확인

사용자는 같은 날 후속 대화에서 “discord: 직접 캡처, whatsapp: 인터넷에서 참고”라고 설명했다. Discord 이미지는 사용자 직접 캡처, WhatsApp 이미지는 인터넷에서 가져온 참고 이미지로 구분한다. WhatsApp의 원래 URL과 실제 앱·리디자인 여부는 확인 필요다.

## 목록 접근 경로와 추가 사진에 대한 후속 확인

사용자는 기존 카카오톡 목록에서 상대를 선택하면 다른 창을 닫지 않고 바로 접근할 수 있다고 확인했다. 따라서 최초에 창을 하나씩 닫았던 행동을 시스템이 요구하는 필수 절차로 해석하지 않는다.

사용자가 추가로 설명한 상태 구분은 다음과 같다.

- 목록이 열려 있을 때: 목록과 여러 대화창이 함께 나타나고, 목록에서 목표 대화를 선택할 수 있다.
- 목록을 닫았을 때: 대화창들만 보이는 상태가 되며, 사용자는 Dock 아이콘 우클릭 → Friends 또는 Chats를 선택해 목록을 다시 연다고 설명했다.
- 세 번째 이미지에서 Dock 문맥 메뉴의 Friends와 Chats 항목이 실제로 확인된다. 정적 이미지로 우클릭과 항목 선택 전체의 동작을 입증한 것은 아니다.

첫 번째 추가 이미지에서는 왼쪽 Chats 목록 창과 세 대화창이 보여, 이 이미지의 네 창은 목록 1개와 대화 3개로 구분한다. 두 번째 추가 이미지의 캡처 영역에는 그 세 대화창이 보이고 목록 창은 보이지 않는다. 목록을 닫았다는 상태는 사용자 설명과 함께 해석한다. 이미지가 화면 전체를 포함한다고 추정하지 않는다.

원문과 이미지 세 장은 evidence/q3/2026-10-22-followup-message.txt 및 photos/2026-10-22-followup-*.png에 새로 보존했다. 기존 관찰·사진은 수정하지 않았다. 원래 목록 복원에 다른 메뉴나 단축키가 전혀 없다는 주장은 하지 않는다.

## 불편 당시 목록 창 상태에 대한 두 번째 후속 확인

CLI 검토가 '실제 불편 장면에서 목록이 열려 있었는지'를 확인하라고 지적해 사용자에게 물었다. 사용자는 “불편을 겪을 당시 대화창은 열려있었는데, 화면상에는 다른 창들에 의해 가려져 있는 상황이었어”라고 답했다. 원문은 evidence/q3/2026-10-22-followup2-message.txt에 보존했다.

- 질문이 대화 목록(Chats) 창에 관한 것이었으므로 '대화창'은 대화 목록 창으로 해석했다. 사용자에게 재확인하지는 않았다.
- 따라서 불편 당시 목록 진입점은 존재했으나 다른 창에 가려져 보이지 않았다. 사용자가 목록 대신 창을 하나씩 닫은 것은 이 가림 상태에서 택한 우회 행동으로 해석한다.
- 목록을 가린 '다른 창들'이 카카오톡 대화창인지 다른 앱 창인지, 창 개요(네 손가락 제스처)에서 목록 창이 어떻게 보였는지는 확인 필요다.
- 목록을 닫은 상태와 Dock 우클릭 복원 경로는 후속 확인에서 드러난 별도 조건이며 불편을 겪은 장면 자체는 아니다.

## 대화를 한 창에서 여는 기존 설정에 대한 세 번째 후속 확인

CLI 검토가 'A안이 이미 있는 기능일 수 있다'고 지적해 사용자에게 물었다. 사용자는 “음 무조건 채팅목록에서 채팅창을 누루면 별도의 창이 열려”라고 답했다. 원문은 evidence/q3/2026-10-22-followup3-message.txt에 보존했다.

- 사용자 환경에서는 채팅 목록의 항목을 누르면 항상 별도 창이 열린다. 따라서 A(통합 대화 창)는 이 사용자가 아는 범위에서 기존 기능이 아닌 새 제안으로 다룬다.
- 설정 메뉴 전체를 확인했는지, 다른 버전에 비슷한 설정이 있는지는 확인 필요다. macOS 창 개요의 앱별 묶음 설정 사용 여부도 답하지 않았다.
