# 카카오톡과 WhatsApp 및 Discord의 PC 화면 구조 비교

## 비교 범위

동일한 기기·버전·과업으로 수행한 실험이 아니라 사용자가 제공한 정적 이미지의 화면 구조 비교다. 현재 제품 전체의 동작이나 성능을 비교한 결과로 읽지 않는다. 파일의 OS 외형만으로 실제 앱 버전·구현·출처를 확정하지 않는다.

사용자 추가 확인: Discord는 본인이 직접 캡처했고 WhatsApp은 인터넷에서 가져온 참고 이미지다. WhatsApp 원래 URL과 이미지 제작 맥락은 확인되지 않았다.

## 해석에서 주의할 부분

WhatsApp 이미지에서 강조된 목록 행은 Joe지만 오른쪽 대화 상단 이름은 RegisSaffi다. 따라서 이 이미지로 선택한 상대와 상단 이름의 일치가 실제로 작동한다고 입증할 수 없다. 편집·리디자인 여부나 실제 화면 출처는 확인 필요다. 왼쪽 목록과 오른쪽 내용의 배치만 참고한다.

Discord 캡처는 서버·채널 UI다. 친구와의 개인 대화로 돌아가는 카카오톡 과업과 동일하지 않다. 또한 Kakaotalk Reference.png에는 Discord로 보이는 화면이 둘 이상 있어 'Discord는 항상 한 창만 쓰므로 다중 창 문제가 없다'고 주장할 수 없다.

## 설계에 반영할 부분

1. WhatsApp 참고 이미지의 목록·내용 병렬 배치를 통합 대화 모드의 레이아웃 참고로 사용한다.
2. Discord 캡처의 탐색 영역과 내용 영역 구분, 선택한 채널의 문자 표시를 참고한다. 서버·채널 계층 전체를 카카오톡에 추가하지 않는다.
3. 카카오톡 과업에서는 최근 열었던 상대의 목록과 현재 대화 한 개를 두고 명확한 이름·선택 피드백을 제공한다. 목록의 위치 유지, 대화별 초안 보존, Dock에서 기본 통합 창 복귀는 이 프로젝트의 설계 요구다. 비교 앱 캡처에서 관찰한 기능으로 쓰지 않는다.
4. 통합 창의 효과는 기존 구조와 같은 과업·조건에서 전체 복귀 시간·오선택·창 정리 행동을 측정해 평가해야 한다.

## 목록 복원 경로를 확인한 뒤의 설계 판단

추가 이미지와 사용자 설명으로 카카오톡도 목록 창이 열려 있으면 다른 대화창을 닫지 않고 상대를 선택할 수 있음이 확인됐다. 목록을 닫은 상태에서는 사용자가 Dock 우클릭 메뉴의 Friends/Chats를 선택해 복원한다고 보고했다. 따라서 비교의 쟁점은 목록 기능의 유무가 아니라 목록이 보이지 않을 때의 탐색 진입점이다.

이번 선택안은 통합 창으로 바꾸는 A에서 각 대화창의 '대화목록' 버튼을 두는 B로 조정했다. WhatsApp·Discord에서 참고한 탐색 영역의 배치를 그대로 복제하기보다, 이미 작동하는 카카오톡 목록으로 돌아가는 제어를 현재 대화 화면에 드러내는 데 적용한다. 이전 통합 창 모형은 대안으로 보존한다. 성능 비교 결과에 따른 선택 변경은 아니다.
