# Codex–Claude CLI 협업 절차

## 역할과 범위

- 사용자는 이 Codex 채팅에서 요청과 판단을 전달한다. Codex가 현재 문항·단계를 정리하고 자료 확인, Claude 호출, 결과 대조, 작업 파일 갱신을 맡는다.
- Claude는 필요한 순간에 별도 관점의 검토·초안·독립 계산을 제공한다. Claude의 응답 자체를 강의 근거나 검증 완료 결과로 취급하지 않는다.
- 검토가 필요한 주장, 계산, 논리 연결이 있을 때 호출한다. 모든 단계에 자동으로 호출하지 않는다.
- AGENTS.md와 각 `work/q*/README.md`의 문항별 조건을 우선한다. 최종 답안은 사용자가 별도로 요청한 뒤 작성한다.

## 호출 설정

- Claude Code는 이 프로젝트에서 `claude-opus-5-5`, effort `medium`을 사용한다. `.claude/settings.json`에도 같은 값을 둔다.
- Codex가 비대화형으로 호출할 때도 매번 `claude -p --model claude-opus-5-5 --effort medium`을 명시한다. `opus` 별칭이나 자동 대체 모델을 사용하지 않는다.
- 기본 호출은 새 세션이다. 이전 Claude 대화의 `--continue`·`--resume`을 사용하지 않는다. 검토 요청은 읽기 전용 도구로 시작하고, 파일 수정은 Codex가 맡는다.
- 일반 검토의 호출 형태는 아래와 같다. 필요한 자료와 검토 질문은 매번 구체적으로 지정한다.

  ```bash
  claude -p --model claude-opus-5-5 --effort medium \
    --tools "Read" --disallowedTools "mcp__*" \
    --no-session-persistence --output-format json "<검토 요청>"
  ```

- 기존 결과를 보지 않는 독립 검산은 `--bare --tools "" --disallowedTools "mcp__*"`로 파일·MCP 도구를 끄고, 원자료와 확정 정의를 요청문에 직접 넣는다. 이 방식은 입력을 제한하기 위한 것이며 폴더 자체의 접근 통제라는 뜻은 아니다.
- 호출이 실패하거나 응답 메타데이터의 실제 모델이 `claude-opus-5-5`가 아니면 그 결과를 채택하지 않고 사용자에게 알린다. 사용량 한도에 닿으면 추가 결제로 전환하지 않고 중단한다.

## 한 번의 검토 흐름

1. Codex가 문항과 검토 질문을 좁히고, 필요한 시험 원문·강의 PDF 페이지·정의·작업 파일을 확인한다.
2. Claude에는 검토 목적, 읽을 자료, 판단 기준, 원하는 출력 형식을 명시한다. 독립 검산이나 최초 응답처럼 선행 결과를 가려야 하는 경우에는 해당 파일과 대화 내용을 전달하지 않는다.
3. 결과가 실제 판단에 쓰이면 `work/q*/reviews/`에 호출 프롬프트와 Claude의 원응답·모델 정보를 각각 저장한다. 기존 기록을 덮어쓰지 않는다. Q1(a)의 최초 응답은 예외로, 시험 지침에 따라 `evidence/q1/`에 원본을 보존한다.
4. Codex가 Claude의 지적을 원본 PDF와 계산으로 대조한다. 채택·기각·확인 필요를 구분해 문항별 `work/` 분석에 반영하고, 이 채팅에서 핵심 판단을 보고한다.

## 문항별 주의점

- **Q1(a):** 최초 답변은 프로젝트 맥락이 없는 별도 새 대화에 시험 프롬프트만 제공해 확보한다. 현재 프로젝트의 Claude CLI 검토 호출로 대체하지 않는다. 확보한 원문을 보존한 뒤 (b) 이후의 검토에 사용한다.
- **Q2:** 시험 원자료와 강의 정의를 먼저 대조하고 Codex가 코드 계산·명시적 검산을 수행한다. 추가 독립 검산이 필요하면 Claude의 새 세션에 원자료와 확정 정의만 제공하고, 기존 결과·풀이·스크립트는 주지 않는다. 현재 독립 검산 기록은 `work/q2/independent-check.md`에 있으므로 단지 Claude를 사용하기 위해 반복하지 않는다.
- **Q3:** Claude는 확보된 관찰·인터뷰·사진·스케치와 강의 근거를 검토할 수 있다. 수행하지 않은 관찰이나 테스트의 결과를 만들지 않는다.

## 답안 작성 단계

사용자가 최종 답안을 요청하면 검증된 `work/` 분석과 원본 근거로 한국어 초안을 작성한다. `humanizer-kr`는 의미·강의 용어·인용·주장 강도를 유지하는 문장 편집에만 사용한다. 제출 전 원본 PDF 파일명과 1부터 시작하는 PDF 페이지, 실제 관찰과 추론의 구분, 계산 결과를 다시 확인한다.
