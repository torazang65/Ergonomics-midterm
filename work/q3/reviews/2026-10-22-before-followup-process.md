## 2. 공감과 관찰

### 과업 중심 페르소나

Mac에서 학습 자료와 여러 앱을 열고 과제·공부를 하며 필요할 때 친구의 카카오톡 대화로 돌아가 질문하는 학생. 사용자 본인 1명의 사례에 근거한다. 나이·전공·숙련도·사용 빈도·성격은 부여하지 않았다.

목표는 원하는 친구의 대화로 복귀해 과제 질문을 하는 것이다. 직접 보고된 페인 포인트는 창 개요에서 목표를 찾지 못하고 앱을 연 뒤에도 창을 하나씩 닫았다는 점이다. 오발송, 학습 내용 망각, 스트레스의 정도는 확인되지 않았다.

| 단계 | 행동·접점 | 확인된 불편 | 설계 기회 |
|---|---|---|---|
| 학습 | 집에서 Mac으로 과제·공부 | 이 단계의 불편은 별도 보고되지 않음 | 메신저로 복귀하는 경로 고려 |
| 창 개요 | 네 손가락 제스처로 Mission Control 형태의 개요 열기 | 친구의 대화창을 바로 찾지 못함 | 앱 식별과 상대 식별을 구분해 지원 |
| 앱 활성화 | Dock에서 카카오톡 열기 | 창 4개가 함께 나타남 | 기본 복귀 대상으로 한 개의 통합 창 제시 |
| 목표 탐색 | 창을 하나씩 닫으며 친구의 창 찾기 | 질문에 앞서 창 정리 행동이 생김 | 다른 창을 닫지 않고 대화 선택 |

「laddering & CJM.pdf」 PDF p.17-18의 실제 조사 기반 페르소나, 시간순 접점과 지표를 참고했다. 감정 점수나 추가 인터뷰를 생성하지 않았다.

## 3. 문제 정의와 원인 후보

## 4. 아이디어 도출과 선택

HMW: 어떻게 하면 학습 중 카카오톡으로 돌아온 학생이 다른 대화창을 닫지 않고 원하는 친구의 대화를 식별하고 선택할 수 있을까?

분석자가 창 제시 방식 변경, 상대 식별 강화, 현재 필요한 대화 지정의 방향으로 대안을 구성했다. 사용자와 집단 브레인스토밍을 수행한 것으로 기록하지 않는다.

| 대안 | 기대 효과 | 실현 가능성 | 새 부담·오류 | 검증 방법 |
|---|---|---|---|---|
| A 통합 대화 창 | 앱 복귀 시 한 창을 제시하고 최근 열었던 대화를 안정된 목록에서 선택. 겹침·닫기 행동 감소 가능 | 앱의 창 관리·상태 보존 수정 필요. 실제 제품 적용 난이도는 미확인 | 목표가 마지막 대화와 다르면 앱 선택 후 대화 선택이 추가됨. 동시 비교에는 불리 | 전체 복귀 시간, 닫기·선택 행동, 잘못된 대화 선택 |
| B 개별 창 식별 강화 | 창 상단의 상대 이름·프로필·보조표시 확대 | 제목·상단 표시 수정 필요. OS 축소 화면에서 가독성 확인 필요 | 다중 창·겹침이 남고 표식도 축소됨 | 같은 크기·창 수에서 목표 탐지 비교 |
| C 현재 사용할 대화 고정 | 사용자가 필요한 대화를 지정해 복귀 시 접근하기 쉽게 제시 | 앱 내 고정 기능 설계와 상태 저장 필요 | 사전 지정 부담, 목표가 바뀌면 낡은 고정이 방해 가능 | 고정 여부·목표 변경별 시간과 조작 비교 |
| D 기존 목록에서 상대 재선택 | 목록 창에서 목표 상대를 선택하는 경로로 창 정리를 피할 수 있는지 검토 | 현재 버전에서 기존 대화창을 전면에 표시하는 조건 등 재현 필요 | 목록 찾기·상대 찾기·창 활성화가 추가될 수 있음 | 관찰된 경로 및 A와 전체 복귀 시간·정리 행동 비교 |

프로토타입 대상으로 A를 선택한다. 사용자가 보고한 여러 창의 동시 제시와 닫기 행동에 직접 대응하기 때문이다. B는 겹침이 남고 C는 사전 지정에 의존한다. D가 같은 불편을 충분히 해소한다면 기존 경로의 발견 가능성을 높이는 개선이 적절할 수 있다. A의 선택은 검증할 설계 가설이며 성능 우위가 입증된 결과는 아니다. A에서도 이름·프로필은 기본 식별 단서로 사용한다.

PC UI 비교는 work/q3/pc-ui-comparison.md에 기록했다. WhatsApp 참고 이미지의 목록·내용 병렬 배치, Discord 서버·채널 화면의 탐색·내용 영역과 선택 표시를 참고한다. WhatsApp의 강조된 목록 이름과 내용 상단 이름이 달라 선택 일치의 증거로 쓰지 않는다. 두 캡처에서 Dock 동작·상태 보존·성능을 추정하지 않는다.

## 5. 프로토타입

카카오톡 데스크톱의 통합 대화 모드를 제안한다. 화면의 친구 가·나·다와 메시지는 가상 예시다. 실제 앱이나 OS 동작을 변경한 것은 아니다.

- 기본 모드에서 대화를 한 창 안에서 관리한다. Dock 복귀 시 대화 수만큼 창을 함께 올리지 않는 동작을 제안한다.
- 왼쪽 목록에 최근 열었던 상대의 이름과 프로필을 표시한다. 기존 항목의 위치는 메시지 도착·선택 때문에 자동으로 바꾸지 않고 새 대화는 끝에 추가한다. 대화가 많아질 때의 탐색 부담은 후속 검증 대상이다.
- 오른쪽에 선택한 대화 한 개를 표시한다. 목록의 선택 표시와 대화 상단 이름을 일치시키고 색과 '선택됨' 텍스트를 함께 사용한다.
- 대화별 작성 중 초안과 읽던 위치를 유지한다. 초안 보존은 모형에서 예시로 작동하며 실제 앱의 스크롤 위치 보존은 구현 요구다.
- 동시 비교가 필요할 때만 '별도 창으로 보기'를 선택하고 '통합 창으로 복귀'해 다시 합친다. 예외 모드의 OS 활성화 동작은 실제 구현 시 확인해야 한다.
- 현재 모형의 별도 보기는 같은 화면 내부의 패널로 시연한다. 실제 OS 새 창 생성·분리·재결합은 구현하지 않았다.
- 상대 선택만으로 메시지를 보내지 않는다. 모형의 입력 내용은 실제로 전송되지 않는다.

예상 흐름: 학습 → 앱 복귀 → 유지된 대화 확인 → 필요하면 목록에서 목표 선택 → 상대 확인 후 질문. 목표가 마지막 대화와 다르면 선택이 추가되므로 클릭 수 감소를 보장하지 않는다.

## 6. 테스트 계획

상태: 미수행. 「2장 보충 인간공학 연구방법론.pdf」 PDF p.22-23, 32의 가설·변수 설정과 과제 모의 실험에 근거한 계획이다.

가설: 통합 창은 다른 대화를 닫는 행동과 전체 복귀 시간을 줄이면서 잘못된 대화 선택을 늘리지 않을 것이다.

1. 사용자 본인으로 절차를 점검하는 1인 예비 평가를 제안한다. 다른 학생에 대한 효과를 입증하지 않으며 여건이 되면 참가자를 추가한다.
2. 기존과 개선 구조를 같은 도구·충실도의 모형으로 비교한다. 실제 앱과 정적인 그림의 시간을 바로 비교하지 않는다. 현재 A 모형만으로 비교 실험이 완료되는 것은 아니다.
3. 시작은 학습 화면에서 복귀 지시가 주어진 시점, 종료는 목표 대화 표시 후 참가자가 상대 이름을 확인한 시점이다. 창 개요·Dock·앱 내 선택을 모두 포함한다.
4. 다른 앱과 대화 수, 상대·메시지, 배율·해상도, 목표를 맞춘다. 기존의 독립 대화창과 A 내부 대화에 같은 정보를 쓴다. 사용자의 '창 4개'를 '대화 4개'로 환산하지 않는다. 모형에 네 대화를 배치한 것은 가상의 설계 예시다. 창 배치도 기록한다. 기존 조건에서 창 닫기를 강제하지 않고 목록에서 상대를 재선택하는 경로도 허용한다. 목록·검색·창 전환 등 제공하는 경로는 조건별로 명시한다.
5. 목표가 마지막 대화인 경우와 다른 대화인 경우를 포함한다. 조건 순서를 교차하고 난이도가 비슷한 과업을 배정해 학습 영향을 줄인다. 한 사람의 반복을 독립된 여러 참가자로 세지 않는다.
6. 시간 측정 중에는 생각 말하기를 요구하지 않는다. 과업 직후 막힌 지점과 식별 단서를 묻는다.
7. 전체 복귀 시간 중앙값, 사용자의 잘못된 대화 선택, 창 닫기·최소화 횟수, 완료 여부, 직후 어려움 1-7점을 기록한다. 자동 복원된 비목표 대화와 사용자의 오선택은 구별한다.

판단 기준 제안: 두 목표 조건에서 완료율이 낮아지지 않고 오선택이 늘지 않으면서 시간 중앙값이 줄어드는지 확인한다. 창 닫기는 보조 지표다. 기존 조건도 닫기가 0일 수 있으므로 감소를 필수 기준으로 삼지 않는다. 일부만 충족하면 구조·목록 폭·표시를 수정한다. 임의의 개선율을 입증값이나 보편적 기준으로 제시하지 않는다.

실행 전 정할 절차 예시: 각 구조를 1회씩 연습한 뒤 구조별 4시행(마지막 대화 목표 2회·다른 대화 목표 2회)을 실시한다. 구조 순서와 목표 순서는 교차한다. 60초 안에 상대 확인까지 못 하면 중단·미완료로 기록한다. 이는 예비 평가용으로 제안한 횟수·중단 기준이며 강의의 표준이나 실제 결과가 아니다. 오선택은 사용자 조작으로 목표 외 대화가 표시된 사건으로 정의하고 자동 복원된 화면은 별도 기록한다. 현재 모형만 사용한다면 상대 선택·초안 보존의 앱 내부 평가로 한정하며 전체 복귀 시간 평가는 두 복귀 모형을 준비한 뒤 수행한다. 평가 지표는 소개 PDF p.51, 53의 사용성 틀과 연결한다.

## 7. 제출 준비와 추가 자료

- 답안 초안: output/q3-answer-draft.md. 미측정 수치·테스트 결과를 쓰지 않는다.
- 기존 창 개요·겹침 캡처와 추가 자기보고로 문제 제기와 설계 제안은 가능하다.
- 실제 테스트에는 기존 구조 모형도 필요하다. 수행 전에는 테스트 계획으로 표시한다.

강의 원리의 관련성은 기존 PDF로 설명 가능하다. 이번 문제의 약점은 추가 이론보다 실제 접근 경로와 원인 단서에 있어, 논문·AI 응답 수를 늘리는 것보다 위 자료를 먼저 확보한다. 실제 테스트 수행 요구에 대한 교수자 추가 공지가 있다면 확인하되, 시험지의 5단계 지문과 4단계까지의 답안 칸만으로 실수행 필수 여부를 임의 확정하지 않는다.
