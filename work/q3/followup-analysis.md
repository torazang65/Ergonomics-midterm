# 창 개요에서 카카오톡 대화창을 찾는 문제 분석

## 문제의 재초점

2026-10-22 사용자 지적에 따라 문제를 최초 기록(evidence/q3/observation.md)의 핵심으로 되돌렸다. Mac 창 개요에서 다른 앱 창들은 비교적 빨리 찾지만, 카카오톡은 채팅마다 창이 하나씩 생겨 원하는 상대의 창을 찾기 어렵다.

후속 확인 과정에서 문제를 '가려진 목록 진입점'으로 좁혔던 판본(선택안 B, 대화목록 버튼)은 work/q3/reviews/2026-10-22-before-refocus-*에 보존했다. B는 다음 이유로 핵심에서 벗어났다고 판단했다.

- 목록에서 상대를 고르면 해당 대화창이 앞으로 오는 기능은 현재 카카오톡에도 있다(사용자 확인). B는 그 앞에 버튼 하나를 더하는 정도다.
- 불편이 시작된 창 개요 단계에서는 B가 작동하지 않는다.
- 채팅마다 창이 쌓이는 구조가 그대로 남는다.

후속 확인으로 얻은 사실은 근거로 쓴다. 목록 선택은 이미 작동하지만 불편 당시 목록은 다른 창에 가려져 있었다(자기보고, '대화창'을 목록 창으로 해석). 채팅 목록에서 채팅을 누르면 항상 별도 창이 열리고, 한 창에서 여는 설정은 사용자가 알기로 없다.

## 강의 원리와 원인 가설

1. 유사성에 의한 묶음과 과업의 불일치(창 개요 단계): 카카오톡 대화창들은 같은 배경색과 배치를 공유해 유사성 원리에 따라 하나의 묶음으로 지각되기 쉽다(「3장 보충 2026.pdf」 PDF p.71, 101). 3장 PDF p.102는 묶음이 과업 요구와 맞아야 한다고 한다. 이 묶음은 카카오톡을 알아보는 데는 맞지만, 그 안에서 친구 한 명을 고르는 과업과는 맞지 않는다. 원문 예는 공간 근접에 의한 묶음이므로 해석적 적용이다. 묶음 안의 개별 창을 구별하려면 세부를 보는 초점 처리가 필요하다(같은 자료 PDF p.89). 반면 다른 앱 창들은 내용과 모양이 서로 달라 이 단계가 덜 필요하다.
2. 작은 이름 글자(창 개요 단계): 시각은 대상 크기와 거리로 정해지고 시력은 세부를 식별하는 능력이다(「5장 보충 vision and visual acuity.pdf」 PDF p.9). 썸네일로 줄면 이름 글자의 시각이 작아져 이름을 읽어 구별하기 어려워질 수 있다. 화면 거리·글자 크기를 측정하지 않았고 사용자가 이름을 읽지 못했다는 기록도 없으므로 방향의 추론에 한정한다. 텍스트는 글자끼리 헷갈리지 않는 식별성이 필요하고(「6장 디스플레이 보충 2026.pdf」 PDF p.23), 중요한 정보일수록 크게, 따로 보여야 한다(같은 자료 PDF p.24). 지금은 상대를 구별하는 가장 중요한 정보인 이름이 창 상단에 작게 있다.
3. 과업 단위와 창 단위의 불일치: 과업의 단위는 '친구 한 명'인데 창의 단위는 '열어 둔 채팅 하나'다. 열린 채팅이 늘수록 골라야 할 비슷한 창도 늘어난다. 구조화된 탐색에서도 항목의 위치 순서에 따라 탐지 시간이 늘어난다(「3장 보충 2026.pdf」 PDF p.98). 창 개요의 배치는 이름 순서 같은 탐색 안내 정보를 주지 않으므로, 비슷한 창을 하나씩 확인하게 될 수 있다. 이는 p.98(안내 정보가 있으면 구조화된 탐색)과 대비한 추론이며 p.97은 탐색 시간을 다루는 시각 탐색 모형의 문제 제기로만 인용한다.
4. 탐색 안내의 가림(Dock 이후 단계): Dock으로 돌아갔을 때 메뉴처럼 탐색을 안내할 수 있는 목록 창(p.98)은 다른 창에 가려져 있었다고 사용자는 답했다. 그래서 사용자는 겹친 창을 하나씩 닫으며 확인했다. 창 닫기는 필수가 아니었고 사용자가 택한 우회 행동이다.

이 구조는 작업을 사람에게 맞추는 설계(「Lecture 1 인간공학 소개 2026.pdf」 PDF p.25)와 거리가 있다. 원문은 PDF 추출로 확인했고, 그림 중심인 3장 p.71과 6장 p.32는 렌더링해 확인했다. 원인은 가설이며 효과는 검증하지 않았다.

## 대안의 재평가

브레인스토밍은 원인별로 대안을 하나 이상 낸 뒤 효과·실현 가능성·새 부담·검증 가능성으로 비교하는 방식으로 정리했다.

| 대안 | 대응 원인·인지적 한계 | 비용·새 부담 | 판단 |
|---|---|---|---|
| A 통합 대화 창 | 유사성·과업 단위 불일치(창 개요에 비슷한 창 여러 개가 아니라 구별되는 창 하나), 탐색 안내(창 안의 대화 목록이 항상 보임) | 창 관리 구조 변경, 목표가 마지막 대화와 다르면 목록 선택 한 번 추가, 기존 습관 변화, 동시 비교 시 분리 필요 | 선택 |
| B 대화창 상단 대화목록 버튼 | 탐색 안내의 가림 | 목록 선택은 이미 존재, 창 개요 단계·창 누적 그대로 | 제외. A의 왼쪽 목록이 가림 문제까지 흡수 |
| C 개별 창 식별 강화 | 유사성·작은 글자(큰 상대 이름) | 창이 여러 개인 구조 유지, 썸네일 축소율에 따른 한계 | A의 보조(분리한 창에 적용) |
| D 기존 목록 경로 안내 | 기억 의존·발견 가능성 | 창 개요 단계와 가림은 그대로 | 비교 기준 |

선택은 A다. 불편이 시작된 창 개요 단계에서 카카오톡이 비슷한 창 여러 개가 아니라 구별되는 창 하나로 나타나게 하고, 그 안에서는 항상 보이는 대화 목록에서 이름으로 고르게 하기 때문이다. 사용자 환경에는 한 창에서 대화를 여는 기능이 없다(자기보고). 실험 결과가 아닌 설계 판단이다.

## 선택안의 동작 요구

- 기본은 통합 창 하나다. 왼쪽에 기존 대화 목록(검색 포함)을 그대로 두고, 오른쪽에 선택한 대화를 둔다. 목록에서 대화를 열어도 새 창을 만들지 않는다.
- 창 제목과 대화 상단에 현재 상대 이름을 크게 표시한다(6장 p.24). 목록의 선택 행은 테두리·배경과 '선택됨' 문자로 표시한다. 선택 표시와 상단 이름을 대조해 맞는 상대인지 판단하는 일은 함께 처리하는 비교 판단이므로 한 창 안에 가까이 둔다(「6장 디스플레이 보충 2026.pdf」 PDF p.32의 근접 부합성, 이 비교 판단에 한정). 결과를 바로 확인하게 해 평가차를 줄인다(「8장 콘트롤 보충.pdf」 PDF p.4). 색만으로 선택을 구분하지 않는다.
- 대화별 초안과 읽던 위치를 유지한다.
- 여러 대화를 나란히 봐야 할 때만 '별도 창으로 보기'로 분리하고 '통합 창으로 복귀'로 되돌린다. 분리한 창이 늘면 원래 문제가 다시 생기므로 분리한 창에는 C의 큰 상대 이름을 적용한다.
- 채팅마다 창을 여는 기존 방식은 설정으로 남겨 습관 변화의 부담을 줄인다.
- 모형 범위: work/q3/kakao-return.html은 통합 창 안의 대화 선택, 창 제목·상단 이름 갱신, 선택 표시, 대화별 초안 유지, 같은 화면 위 패널로 단순화한 별도 보기를 구현했다. 검색, 실제 OS 창 분리·창 개요·Dock 동작, 읽던 위치 보존, 기존 방식 설정은 구현하지 않았다.

## 평가 범위

과업은 창 개요에서 시작해 지시받은 상대의 대화를 열고 이름을 확인하는 것이다. 기존 구조(채팅마다 창)와 A를 같은 충실도의 모형으로 비교하며, 목표가 마지막 대화인 경우와 다른 대화인 경우를 모두 포함한다. 기존 조건에서는 목록 선택·Dock 메뉴·창 닫기 등 모든 경로를 허용한다. 열린 채팅 수, 다른 앱 창 수, 목록 창의 열림·가림 상태, 상대 정보, 화면 조건을 두 조건에서 같게 두고, 참가자 간 비교 또는 조건 순서 상쇄로 학습 효과를 줄인다. 사용자 본인은 설계 의도를 알고 있어 첫 사용 측정 대상이 될 수 없다. 현재 모형으로는 창 개요를 포함한 전체 시간을 측정할 수 없어, 비교 모형 준비 전에는 통합 창 안의 상대 선택과 초안 유지의 형성 평가만 제안한다. 모든 평가는 미수행이다.
